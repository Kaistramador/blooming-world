## 4. Протокол GitHub-сохранения (без Cloudflare)

> Урок SciFi Mahjong (их Task 102): откат песочницы уничтожил незапушенные коммиты локально — выжило только то, что было на GitHub. Отсюда правило: **пуш в конце КАЖДОЙ сессии ОБЯЗАТЕЛЬНО**, до закрытия задачи.

1. **Конфиг** — в `.env` корня проекта (файл в синк не попадает, токен никогда не печатается и не коммитится):
   - `GITHUB_TOKEN=…` — fine-grained PAT (или classic со scope repo). Выдаётся игроком на github.com: Settings → Developer settings → Fine-grained tokens → доступ только к целевому репозиторию → Repository permissions → Contents: **Read and write**.
   - `GITHUB_REPO=owner/name` — целевой репозиторий (по умолчанию — репозиторий SciFi Mahjong; имя подскажет игрок или ассистент найдёт через API по токену).
   - `GITHUB_TARGET_FOLDER=blooming-world` — отдельная папка внутри репозитория; пусто = корень (тогда это «отдельный репозиторий под игру»).
2. **Синк** — `bash scripts/sync-github.sh "Task N: суть"`: клон → `reset --hard origin/main` (наше содержимое всегда живёт в проекте, чужие файлы репо обновляются из origin) → rsync зеркала в `blooming-world/` (исключения — `scripts/sync-exclude.txt`: node_modules/.next/.env/upload/базы/логи) → коммит → пуш с авторизацией через http.extraheader (токен не остаётся в .git/config). Если origin уехал вперёд (пуши SciFi-сессий) — скрипт сам повторяет fetch/rebase-цикл до 3 раз.
3. **Правила**: (а) файлы SciFi Mahjong в репозитории НЕ трогаем — их STATE.md ведут их сессии; (б) секреты в репозиторий не попадают — перед пушем проверяется отсутствие .env/токенов в индексе; (в) сообщения коммитов: `blooming-world: Task N: …`; (г) собственный git-репо проекта (`/home/z/my-project`) — локальный снимок для диффов, защита прогресса = только GitHub-пуш.

## 5. Решения и уроки (§-правила проекта)

- **§5.1 Графика/эволюция**: порядок оттенков фишек одинаков во всех 10 эрах (Okabe-Ito якоря: красный #c74134, жёлтый #f6e04b, зелёный #2ea56d, синий #3d9be0, фиолетовый #b06fc9, оранжевый #ef8f2a). Эры эволюционируют насыщенностью/светлотой/кантами/эффектами. Новый контент обязан сохранять форму-кодирование (`shapes.ts` — силуэт определяется цветом, скины меняют только внутреннюю графику).
- **§5.2 Доступность**: минимальный стандарт — любой новый элемент поля различим БЕЗ опоры на цвет (форма/символ/кант/движение). Камни ≠ фишки: восьмиугольник + пипсы HP. Спец-маркер всегда белый на тёмном диске.
- **§5.3 Юридическая чистота**: оригинальные названия («Цветущий мир»/Blooming World, спец-фишки самоименованные), графика CSS-оригинальная, из жанра берутся только неохраняемые механики. Никаких ассетов/имён/выражений из Candy Crush/Royal Match и прочих игр.
- **§5.4 Сейвы**: ключ persist `blooming-world-save-v1` не менять; структурные изменения стора — только аддитивные (поля с дефолтами), версию persist поднимать при несовместимых изменениях.
- **§5.5 Архитектура**: движок (`engine.ts`, `levels.ts`) — чистый TS без DOM: подготовка к будущему порту на React Native. UI-слой — единственное место, где живут CSS/анимации.
- **§5.6 Без Cloudflare** (решение игрока от 07.11): никакой деплой-цепочки; сохранение прогресса разработки — только GitHub. Если позже понадобится прод — отдельное решение игрока.
- **§5.7 Проверка перед закрытием Task**: `bun run lint` + `bunx tsc --noEmit` (игнор examples/ и skills/ — шаблонные) + при правках движка — `bun scripts/test-engine.ts` + браузерный смок ключевых сценариев.
